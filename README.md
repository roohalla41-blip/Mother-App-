# مادر هاب (Mother Hub)

پایه اجرایی پلتفرم معرفی، انتشار، دانلود و پشتیبانی محصولات نرم‌افزاری؛ مطابق سه سند ساختاری موجود در مخزن.

## ساختار پروژه

- `src/App.jsx`: مسیریابی، صفحات عمومی، ورود و پنل سازنده
- `src/lib/supabase.js`: اتصال امن سمت کلاینت و توابع دریافت داده
- `src/styles.css`: رابط واکنش‌گرا با پشتیبانی کامل RTL
- `supabase/migrations/001_initial_schema.sql`: جداول، انواع داده، ایندکس‌ها، triggerها و RLS
- `.env.example`: متغیرهای موردنیاز برای اتصال

## اجرای محلی

1. Node.js نسخه 20 یا جدیدتر نصب باشد.
2. `npm install`
3. از `.env.example` یک فایل `.env.local` بسازید.
4. آدرس پروژه Supabase و کلید anon/publishable را در آن قرار دهید.
5. migration را فقط روی پروژه اختصاصی Mother Hub در Supabase اجرا کنید.
6. `npm run dev`

## احراز هویت پنل سازنده

ورود با Supabase Auth انجام می‌شود. دسترسی پنل صرفاً با نقش ثبت‌شده در `app_metadata.role` برابر `builder` یا `admin` اعطا می‌شود. این claim باید از مسیر مدیریتی مورداعتماد در Supabase تنظیم شود؛ مقدار role از فرم عمومی یا user_metadata پذیرفته نمی‌شود.

## نکات امنیتی مهم

- هرگز `service_role` key را در متغیرهای `VITE_*` یا کد مرورگر قرار ندهید.
- قبل از انتشار عمومی، نقش سازنده، RLS، Storage policies و مسیرهای دانلود را با حساب‌های anon، کاربر عادی و سازنده آزمایش کنید.
- bucket فایل‌ها خصوصی است؛ فایل‌های منتشرشده باید از مسیر امن/لینک امضاشده ارائه شوند. برای استقرار واقعی، منطق تولید لینک امضاشده باید در تابع سروری دارای مجوز پیاده‌سازی شود.
- صفحات حریم خصوصی و شرایط استفاده در این پایه، متن نهایی حقوقی ندارند و پیش از انتشار باید تکمیل شوند.
- نمونه‌های نمایشی رابط فقط وقتی Supabase تنظیم نشده باشد نمایش داده می‌شوند؛ آن‌ها داده واقعی پایگاه داده نیستند.

## وضعیت فعلی

این commit پایه اولیه رابط و طرح پایگاه داده را ایجاد می‌کند. اتصال به پروژه Supabase، اجرای migration، تنظیم claim سازنده، تکمیل مدیریت نسخه‌ها/آپلود و تست build/deploy پس از تأمین تنظیمات محیطی باید انجام شود.
