# برنامه حذف کامل وابستگی Base44

## نتیجه بررسی فایل‌های اصلی (۴ نوامبر ۲۰۲۶)

سه فایل ریشه مخزن بررسی شدند:
- `madar-app-map-2026-11-04.json`: نقشه مسیرهای عمومی، احراز هویت و ۱۲ بخش پنل سازنده.
- `madar-core-structure-2026-11-04.json`: معماری شش‌لایه.
- `madar-db-structure-2026-11-04 (1).json`: طرح ۱۱ جدول پایگاه داده.

## وابستگی‌های Base44 که باید حذف شوند

در نقشه هسته، لایه سوم صریحاً با عنوان **Base44 Functions** تعریف شده و شامل این عملیات است:
- `supabaseCrud`: درگاه CRUD و کنترل مالکیت/دسترسی
- `supabaseStorage`: آپلود، حذف و لینک امضاشده
- `supabaseStatus`: محاسبه مصرف دیتابیس و Storage
- `supabaseKeepAlive`: کار زمان‌بندی‌شده
- `supabaseSetupDatabase`: راه‌اندازی جداول، انواع و سیاست‌ها
- `supabaseTestConnection` و `supabaseTestCRUD`
- `generateSitemap`

این‌ها قابلیت‌های منطقی برنامه‌اند، نه الزاماً سرویس‌هایی که باید حذف شوند. باید پیاده‌سازی وابسته به Base44 جایگزین شود، در حالی که رفتار محصول حفظ شود.

## جایگزینی پیشنهادی

| وظیفه فعلی | جایگزین مستقل |
|---|---|
| Base44 Functions / عملیات امن سرور | Supabase Edge Functions (Deno) |
| CRUD | Supabase client برای عملیات مجاز + Edge Functions برای عملیات حساس |
| کنترل دسترسی | Supabase Auth + PostgreSQL RLS؛ مالکیت سازنده در policy و تابع سرور |
| Storage | Supabase Storage با bucket خصوصی/عمومی و signed URL طبق نوع فایل |
| زمان‌بندی keep-alive | Supabase Cron در صورت نیاز واقعی؛ حذف آن اگر صرفاً برای جلوگیری از خواب سرویس لازم بوده |
| ساخت/تغییر schema | SQL migrations نسخه‌بندی‌شده در `supabase/migrations`؛ نه endpoint عمومی setup |
| تست اتصال و CRUD | تست خودکار و health-check محدود، بدون افشای اطلاعات داخلی |
| sitemap | تولید در build یا route سمت سرور/فایل استاتیک |

## نکات امنیتی مهم

1. کلید `service_role` فقط در Secrets سمت Edge Function؛ هرگز در مرورگر یا GitHub قرار نگیرد.
2. کلید publishable/anon در کلاینت فقط همراه RLS محدود و آزمایش‌شده قابل استفاده است.
3. هیچ endpoint عمومی نباید بتواند نام جدول/ستون دلخواه دریافت کند و CRUD نامحدود انجام دهد.
4. مسیر مخفی یا کد دسترسی ثابت برای سازنده، جایگزین احراز هویت امن نیست. پنل سازنده باید با نقش/عضویت قابل اعتبارسنجی در سمت سرور محافظت شود.
5. ۱۱ جدول طرح موجود حفظ می‌شوند؛ هیچ جدول یا داده‌ای در پروژه Supabase حذف یا بازنویسی نمی‌شود.
6. ساختار و فایل‌های مبنا در ریشه مخزن حفظ می‌شوند تا مرجع مهاجرت باقی بمانند.

## وضعیت اجرایی

این سند فقط تحلیل و طرح مهاجرت است. شاخه کاری مستقل `migration/remove-base44-supabase` از `main` ساخته شده است. هنوز جایگزینی کامل کد، migrationهای SQL، Edge Functions، تست‌ها و انتشار انجام نشده؛ پیش از اعلام تکمیل باید هر مورد پیاده‌سازی و build/test شود.
